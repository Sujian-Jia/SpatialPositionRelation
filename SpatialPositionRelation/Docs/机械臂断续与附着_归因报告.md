## 本工程的机械臂构型

- [原生 `GeometryAt`](../../7DOF_masscenter_real_constraint/DockingDynamics.cpp#L201) 用 `rS + RS * armMount` 和 `RS * armBaseRotation` 定基座。`armMount=(1,0,2)` m，来自 [`DemoSession.hpp`](../Native7Dof/DemoSession.hpp#L99) 的默认工况。关节角是 C++ 模型弧度，零位用 `armOffsets` 与 `armFixedRot`。每关节实际模型约定是转前 frame 本地 +Z、正向 `Rz(q_i)`。[`Parameters.cpp`](../../7DOF_masscenter_real_constraint/Parameters.cpp#L118) 明确写的是 XML 笛卡尔 frame 原点偏移，并非 DH 参数；源码里的实际轴仍须结合实体坐标核验。

## 三处细节的勘察

1. 当前 Qt 的两处独立字符串为 `己方（机械臂与敏感器）` 和 `空间站 · 组内参考模型`。只删除「组内」得到 `己方（机械臂与敏感器）` 和 `空间站 · 参考模型`。附件引用的合并句里「和」及空格与源码实际不同。建议依据「只少两个字」改动第二个字符串。[当前源码](../../Spatial_Qt/SpatialPositionRelation/mainwindowui.cpp#L81)
2. 原实现用相机光心和远端平面四角射线表示矩形截面的视锥。建议用一个半透明、无底面的四面锥 Mesh 替换四个 LineRenderer。顶点与远端四角仍走现有水平/垂直 FOV 和显示长度路径，同一组参数也支持不等 H/V FOV。现有「显示射线」开关、筛选和光心遥测字段沿用。圆或椭圆截面会与现有矩形四角和可见性判定存在几何差异。[现有视锥实现](../Assets/Scripts/SpatialSensorFrustum.cs#L31)
3. 现有未来预警列消费 `futureOcclusion` 与 `futureOcclusionStartSec/EndSec`。历史协议说明已有每路传感器合作目标遮挡的窗口、采样、遮挡累计时长、出场时长及峰值比例，10 s 是旧轨迹的缺省采样间隔，光照仍在实时链路。现工况的原生 CAPI 无前瞻接口或完整会话快照。`Docking_SetState(q,u,mode)` 只恢复部分物理状态，且会重设接触标记和抓捕相对旋转，恢复不了已运行会话的接触/时序历史。[Qt 显示](../../Spatial_Qt/SpatialPositionRelation/telemetrydisplay.cpp#L90) · [旧协议](../../归档/文档/TCP_PROTOCOL.md#L25) · [原 CAPI](../../7DOF_masscenter_real_constraint/DockingCAPI.h#L50) · [SetState](../../7DOF_masscenter_real_constraint/DockingDynamics.cpp#L148)

预警推荐方案②。在 wrapper 新增 `Spr7_Clone`，由原生完整复制 `Session`、`DockingDynamics` 约束历史、接触器、控制器、事件时间、当前步号及时间累加边界，再用 `Spr7_Advance/Read` 在独立会话前向步进。Unity 复用原视场与遮挡判定，使用同标定的独立离屏几何与当前敏感器配置，预测期间不应用到主场景。建议保留现有遮挡指标、以本次 80 s 工况剩余时段为预测窗口，显示时刻使用同一仿真秒。原生物理步长 1 ms 与 20 ms 采样仍适用，UI 几何评估间隔须衡量短窗漏报与开销。暂停停止预测推进，复位和配置变更作废旧预测，倍速仅影响主播放。克隆先验收同一初态、抓捕中、锁紧中三类快照的逐步结果及双会话互不改变，再跑原生两组自检、原 CSV 及真实 Player 回归。变更局限于新增 wrapper、Adapter 和独立预测计算入口，可独立回滚。

## 补证：组内 Prefab 的抓捕接口

组内 `SevenArmRobotController` 在 `服务航天器.prefab:50724` 已序列化七轴节点、所属本体和夹爪组件。其 `baseObject` 指向 `服务航天器的世界坐标`。配套 `GripperController` 在 `服务航天器.prefab:32312` 把 `夹爪` 本身列为 `basePlate`，抓取方向为其局部 `+Z`。参考控制器将被抓取的 `Gripper` 标记点与 `basePlate` 原点对齐（`GripperController.cs:357–365`）。这给出了导入标定可用的原始接触定义。当前 Adapter 采用的 Renderer 包围盒边缘是另一取点。

目标装配内已有可复用的可见捕获轴 `服务航天器/轴`，以及标记为 `Gripper` 的子节点 `轴顶点`。两者在 Prefab 中分别位于第 143072 行和第 94782 行。`轴顶点` 的 `InsertionPoint` 子节点是独立插入基准。按发布场景现有旋转、缩放和端面对齐，目标器 `轴顶点` 的本体局部 Unity 坐标为 `(-0.955, -0.021, -0.238)` m，距原生 `grapple` 的 `(0,0,-1)` m 为 **1.222 m**。此前记录的 **1.408 m** 指空到达标记。现有 Adapter 移动的是该空标记，捕获轴仍在原装配位置。

当前目标舱体显示端面到 `轴顶点` 为 **0.380 m**，原生端口到 `grapple` 为 **1.601 m**。单一刚体配准保持点间距离，因此仅旋转平移整船无法同时对齐这两个点。单看点间距，等比比例需在当前场景基础上约为 **4.21 倍**，对应整船 5.5 m 归一化尺寸约变为 23.2 m，也没有解决固定端或端面轴向的验收。建议用可回滚的组内装配变体，以 `夹爪/basePlate` 和 `轴/轴顶点` 为已知候选实体基准，独立核对原生安装坐标处的舱体接合面和固定轴，再决定最终配准。源 `.prefab` 按原件只读保留。

原生 2,565 个抓捕样本中，自 **8.12 s** 开始直到端口锁紧前，`tool/grapple` 间距持续低于 **1 mm**。自 **10.72 s** 开始持续低于 **1 μm**。这些数值描述原生残差曲线。可将它与 Unity 实体接合误差分别验收，避免把抓捕瞬间的原生残差从画面中抹掉。

第一版通过了挂点检查，但放大 Qt 侧视时仍有一根长杆悬空。实测 FBX 后发现 `关节4实体` 从旧段起点沿轴投影约为 0.559–1.191 m，旧段跨度约为 0.584 m。网格属于下一个长跨度。`关节3实体` 同样从其节点向下一关节伸出。按网格实体 1、2、5、3、4、6、7 重新装配，并从端部顶点计算物理接合基准。导入组内网格维持原材料和来源，Unity 标定长度按 C++ 段长换算。显示端的基座和抓捕座分别登记到各自舱体，夹爪采用参考装配的 `basePlate`。本轮修改集中在场景生成与 Adapter，原生算法和原始交付输入校验通过。
